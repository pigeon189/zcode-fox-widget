# fox-dock 计划（工作名）

> 桌面常驻的「多 agent 成本看板」：把挂件拖到任意 agent 窗口上，自动识别、吸附、切到对应计费口径。
> 本文是立项计划，不含实现。所有默认决策按「用户只说了一句、具体自己安排」来定，可改。

---

## 1. 目标与边界

### 做
- 独立常驻：不依赖任何 agent 启动，登录后自己在。
- 拖拽绑定：拖到某个 agent 窗口上 → 认出它 → 吸附 → 切计费口径。
- 多 agent：首批 ZCode + WorkBuddy，其余走通用适配器（只显示「已绑定，暂不支持计费」）。
- 统一账本：每个 agent 的今日/本轮/配额/余额在一个地方看。
- 独立更新：自己的发布通道、自己的签名与回滚。

### 不做（v1）
- macOS（窗口操作要重写，另立项）。
- 第三方插件市场 / 任意 JS 插件（安全与杀软成本不划算）。
- 云同步、账号体系。
- 改写现有两个挂件仓库的主线代码。

## 2. 架构

```
┌──────────────┐   local HTTP/WS (127.0.0.1, token)   ┌────────────────┐
│   foxd       │◄────────────────────────────────────►│  overlay       │
│ 常驻服务      │                                      │  Electron 浮层  │
│ · 窗口发现    │                                      │ · 拖拽/吸附     │
│ · 绑定表      │                                      │ · 面板 UI       │
│ · 适配器注册  │                                      │ · 气泡/提醒     │
│ · 账本/计费   │                                      └────────────────┘
│ · 自更新      │
└──────┬───────┘
       │ 只读
       ▼
  ZCode sqlite / WorkBuddy.db / transcript / 各厂商 API
```

### 关键契约

```ts
type ProcInfo = { pid: number; startMs: number; exe: string; name: string }
type WinInfo  = { hwnd: string; title: string; cls: string; rect: Rect; dpi: number }
type BindKey  = `${exe}|${pid}|${startMs}|${hwnd}`   // 见验证 3：标题不可靠

interface Adapter {
  id: string
  match(p: ProcInfo, w: WinInfo): number        // 0~1，多个命中取最高
  profile(p: ProcInfo, w: WinInfo): AgentProfile // 工作区/账号/会话线索
  billing(p: AgentProfile): Promise<Billing>     // { today, round, quota, balance, unit }
  ui(b: Billing): UiHints                        // 主数字口径、单位、颜色
}
```

### 身份与绑定
- 绑定键：`exe|pid|startMs|hwnd`（hwnd 消失时用 `exe|pid|startMs` 兜底重绑）。
- 绑定持久化：`%LOCALAPPDATA%\fox-dock\bindings.json`，带 adapterId 与用户覆盖项。
- 一个进程多窗口：hwnd 区分（已验证）。
- 进程重启：pid/startMs 变 → 旧绑定标记 stale，不自动串窗。

### 数据与端口
- 数据目录：`%LOCALAPPDATA%\fox-dock`（**不碰** `~/.zcode` 与 `~/.workbuddy`）。
- 服务端口：固定 39401（占用则 +1，锁文件记录），仅 127.0.0.1。
- 写操作要 token；读操作限制同站（与现有挂件同一套安全观）。

## 3. 工程与仓库

### 分支与工作区
- 分支：`feat/dock`（长分支，不合并回 `main`/`workbuddy`，直到 1.0 再决定）。
- 工作区：`git worktree add E:\WorkSpace\fox-dock feat/dock` —— 与现有两个挂件目录完全隔离，但共享同一个 git 仓库与历史。
- 现有两个挂件线**零改动**；`feat/dock` 上只在 `dock/` 子目录新增，不动 `lib/`、`desktop/`。

### 目录结构（分支内）
```
dock/
  daemon/          # 常驻服务：win32 桥、绑定、适配器注册、账本、更新
  overlay/         # Electron 浮层（页面 + 主进程）
  adapters/
    zcode/
    workbuddy/
    generic/
  shared/          # 类型、身份键、坐标数学
  test/
    unit/
    integration/   # 假 agent（可控窗口/进程/数据库）
    e2e/           # Playwright（Electron）
    visual/        # 截图基线 + 像素对比
  tools/           # cli：start/stop/install/uninstall/doctor
  docs/            # 决策记录、适配器开发指南
```

### 版本与发布
- 版本从 `0.1.0` 起；**所有 0.x 一律 pre-release**（`gh release create --prerelease`）。
- tag：`dock-v0.1.0-pre.1`、`dock-v0.1.0-pre.2`…（与现有 `v*`、`wb-v*` 不冲突）。
- 1.0 之前不发布正式版；1.0 之后才允许非 pre-release。
- 签名：**独立密钥** `dock-release-key.pem`（不复用挂件那把），公钥入库；更新器只认 `dock-v*` 通道。
- CI：新增 `.github/workflows/dock-ci.yml`，只对 `feat/dock` + `dock/**` 生效，不触发现有两线。

### 提交节奏
- 每轮一个可回滚的提交序列，提交信息 `dock: R<n> <做了什么>`。
- 每轮结束打 pre tag（可选，R3 起每轮打），发布 prerelease 供你自己装。

## 4. 测试体系（重点，不让你当 QA）

### 分层
| 层 | 工具 | 覆盖 | 门禁 |
|---|---|---|---|
| 单元 | `node:test` | 身份键、坐标/DPI 数学、账本公式、适配器匹配打分 | 全绿 + 覆盖率 ≥80%（shared/daemon 核心） |
| 集成 | `node:test` + 真 HTTP | 服务 API、绑定表、单实例、热更新、崩溃重启 | 全绿 |
| 假 agent | Electron 小程序 | 可控窗口数/标题/位置/DPI/进程重启，驱动真实 Win32 枚举 | 全绿 |
| E2E | Playwright Electron | 拖拽、吸附、面板交互、绑定持久化、错误态 | 全绿 |
| 视觉 | Playwright 截图 + `pixelmatch` | 浮层位置/尺寸/主题/面板布局 | 差异 ≤0.1%，动态文本用 `data-visual-mask` 遮罩 |
| 压力 | 脚本 | 8 小时 soak：内存/句柄/CPU 曲线、100 次绑定解绑 | 无泄漏、CPU 均值 <1% |

### 假 agent（核心设施）
- 一个 Electron 应用，可配：窗口数（1–3）、标题、位置、是否多屏、是否模拟「重启换 pid」。
- 用途：不依赖真实 ZCode/WorkBuddy，就能测命中、吸附、双窗口歧义、重启失效。
- 适配器测试走 `FOXD_ADAPTER_OVERRIDE=fake`，避免依赖 exe 名。

### 视觉测试怎么防脆
- 关动画（`FOXD_TEST_DISABLE_ANIM=1`）、冻结时钟、固定字体。
- 截图只截浮层矩形（背景放纯色测试窗），避免桌面壁纸干扰。
- 基线图入库；改动 UI 必须显式 `npm run visual:update` 并 review 差异图。
- 明确不断言「渐变像素」这类易漂移的东西，只断言布局/边界/文本块。

### 「不让你当 QA」的边界
自动化覆盖到：功能、交互、布局、崩溃恢复、真实数据读取（用 fixture 库）。
只在这三种情况找你：
1. R2 重启一次，确认自启（脚本会告诉你看哪里、对不对）。
2. 每个适配器上线时，和宿主界面数字对一次（30 秒）。
3. R8 真机手感：拖 3 次（2 分钟）。

## 5. 分轮计划

> 每轮独立可验收；任何一轮不达标就停，不往后堆。

### R0 立项骨架
- 做：建 `feat/dock` 分支与 worktree；目录骨架；`dock-ci.yml`（lint + 空测试）；决策记录模板；本计划入库。
- 测：CI 在空项目上跑通。
- 你要做：无。
- 退出条件：`E:\WorkSpace\fox-dock` 可独立开发，现有挂件 CI 不受影响。

### R1 窗口发现与身份（Win32 桥）
- 做：daemon 内的 Win32 桥（枚举/命中/矩形/DPI/进程信息）；身份键；`doctor` 命令打印当前桌面全部窗口与识别结果。
- 测：单测（键、评分）；集成用假 agent 起 3 窗口，断言命中与排除自身；性能门禁：单次扫描 <2ms。
- 你要做：无。
- 退出条件：`doctor` 在你机器上能正确列出每个窗口的 exe/pid/title/rect，与肉眼一致。

### R2 常驻与自启
- 做：单实例锁、登录启动（启动文件夹快捷方式，安装器自动创建）、watchdog（异常退出 3 秒重启）、`install/uninstall`。
- 测：单实例、kill -9 后自动拉起、卸载干净；CI 里模拟「父进程退出」。
- 你要做：**重启一次电脑**，看托盘/日志里是否自启成功（脚本输出 PASS/FAIL）。
- 退出条件：重启后 30 秒内 daemon 在线；手动 kill 后 5 秒内回来。

### R3 拖拽绑定（浮层核心）
- 做：浮层拖拽手势；拖拽中采样光标下的窗口（已验证 0.13ms）；落点吸附；绑定反馈动画；解绑/重绑。
- 测：Playwright 拖拽到假 agent 的三个位置（中心/边缘/另一窗口）；视觉基线；误拖（拖到桌面/自己）不产生绑定。
- 你要做：无（真机手感留到 R8）。
- 退出条件：拖到假 agent 上 100% 吸附，拖到空白 0 绑定，连续 20 次无错位。

### R4 适配器框架 + generic
- 做：注册表、匹配打分、profile、billing 契约；generic 适配器（识别成功但不支持计费时的 UI）。
- 测：单测打分优先级（同分取更具体的）；集成：未知进程绑定后显示「暂不支持计费」，不崩。
- 你要做：无。

### R5 ZCode 适配器
- 做：复用现有 sqlite 读取逻辑（读 `~/.zcode` 只读），映射到 `Billing`；额度/余额口径。
- 测：seed 一个假 sqlite fixture（多模型/多轮/套餐行），断言今日/本轮/配额；边界（库锁、空库、schema 变更）。
- 你要做：与 ZCode 界面数字对一次（30 秒）。
- 退出条件：fixture 全绿 + 真机数字一致（允许 1 分钱误差）。

### R6 WorkBuddy 适配器
- 做：`workbuddy.db` + transcript 读取；积分口径；上下文余量。
- 测：seed 假库；断点续读/缓存失效；大 transcript 性能（<200ms）。
- 你要做：对一次数字。

### R7 统一账本与多 agent 汇总
- 做：账本 schema（按 agent+账号+币种/积分分开，不混算）；跨 agent 今日总览；导出 JSON。
- 测：表驱动数学用例；迁移测试（旧版本账本升级）；时间边界（跨天/时区）。
- 你要做：无。

### R8 UI 打磨 + 多窗口/DPI/多屏
- 做：绑定管理面板（列表/解绑/切换）、多窗口歧义提示、DPI 缩放、多屏跟随、主题。
- 测：视觉基线 ×3 套（浅/深/125% 缩放用坐标单测+局部真机）；Playwright 面板全流程。
- 你要做：拖 3 次看手感；有第二块屏的话拖一次。
- 退出条件：无遮挡、无错位，120Hz 屏上拖拽不掉帧。

### R9 更新与发布
- 做：独立更新器（下载/验签/替换/回滚）；`dock-v0.x` prerelease 流程；更新失败自动回滚（复用挂件已验证的回滚思路）。
- 测：假更新源注入（成功/校验失败/中断/回滚）；CI 出包并在本地装一次。
- 你要做：装一次 prerelease（1 分钟）。
- 退出条件：更新失败能回滚到旧版且服务自动恢复。

### R10 稳定化 → 1.0
- 做：8 小时 soak、崩溃注入、日志/诊断包（复用挂件的脱敏思路）、文档与适配器开发指南。
- 测：soak 无泄漏；10 次随机 kill 全部自动恢复；诊断包不含密钥。
- 你要做：日常用两天，有异常丢日志给我。
- 退出条件：连续 48 小时无崩溃、无内存增长，才把版本从 `0.9.x` 提到 `1.0.0`（首个非 pre-release）。

## 6. 备选方案（按风险从低到高）

| 方案 | 做法 | 优点 | 缺点 | 何时选 |
|---|---|---|---|---|
| A 只做多目标跟随 | 不做常驻，仍由宿主拉起，只支持「当前前台是谁就跟谁」 | 改动最小，复用现成跟随器 | 不能脱离宿主；无绑定语义 | 只想验证多 agent 观感 |
| B 常驻 + 手动切换 | 不做拖拽，菜单里选 agent | 无 Win32 命中风险，UI 简单 | 少了「拖一下」的核心体验 | 拖拽手感不达标时 |
| C 常驻 + 拖拽（本计划） | 如上 | 体验最好，已验证可行 | 工程量最大 | 默认 |
| D 原生 C# 浮层 | 不用 Electron，Win32/WPF 画浮层 | 体积小、启动快、无 Chromium 停帧问题 | UI 开发慢、复用不了现有前端 | 发行体积/性能成为痛点 |
| E 声明式适配器 | 只允许 JSON 配置（进程名/库路径/价目） | 无代码执行风险 | 复杂口径表达不了 | 需要第三方接入时 |

**默认走 C**；R3 手感不达标降级 B；发行体积被吐槽再评估 D。

## 7. 最终成型效果

- 开机后托盘里有一个小鲸鱼，不依附任何 agent。
- 拖到 ZCode 窗口上 → 吸附到该窗口，显示 ZCode 的今日花费/额度；拖到 WorkBuddy 上 → 切积分口径。
- 关掉 agent、重开、换窗口，绑定按身份键自动恢复或明确失效，不串窗。
- 面板里能看到「这台机器上所有 agent 今天花了多少」，单位不混算。
- 自己在后台更新，失败自动回滚；更新只走 `dock-v*` 预发布通道。
- 现有两个挂件照常工作，互不影响。

## 8. 风险与未验证项

| 项 | 状态 | 应对 |
|---|---|---|
| 拖拽命中/排除自身 | ✅ 已验证（0.13ms） | — |
| 管理员窗口读取 | ✅ 已验证 | 只读，不写宿主 |
| 多窗口/重启身份 | ✅ 已验证 | 键含 hwnd + 启动时间 |
| 常驻存活 | ✅ 已验证（快捷方式启动） | watchdog + 单实例 |
| 多显示器/DPI | ⚠️ 未验证 | R8 专项；无第二屏则做坐标单测 + 虚拟分辨率 |
| 高 DPI 下拖拽落点 | ⚠️ 未验证 | 同上 |
| 杀软误报（常驻 + 自启） | ⚠️ 未验证 | 代码签名、安装器走标准位置、不写注册表自启 |
| agent 数据库 schema 漂移 | ⚠️ 长期风险 | 适配器版本探测 + 失败降级为「暂不支持」 |
| 读其它 agent 数据的隐私观感 | ⚠️ 产品风险 | 首次绑定明确提示「只读本地数据」，可一键解绑 |
