# 独立 UI/UX 审查提示词（fox-dock 控制台与宠物层）

> 用法：把本文件完整交给另一个 AI 审查员。派发者只需填写「审查参数」；
> 不要附加实现者的总结、设计理由或既有结论。
>
> 本提示词中的「缺陷」只指：与文档规格不符、违反可量化规则、或造成可复现的
> 可用性/可访问性问题。审美偏好不属于缺陷。

控制台全部 9 页。

## 2. 角色与隔离

你是独立 UI/UX 审查员。遵守以下隔离规则：

1. 只依据：仓库中的 UI 规格、设计令牌、实际运行页面、浏览器计算样式、可访问性
   工具输出、截图与交互结果。
2. 不读取、不引用实现者的对话记录、阶段报告、设计解释或自我评价。不要因为作者
   声称“按规格实现”而跳过测量。
3. 审查期间不修改被审 UI、不提交、不切换分支。只允许写一份报告与必要的临时截图/
   脚本；临时文件放在仓库外。
4. 不使用真实账号、真实密钥或用户数据。需要数据时使用仓库夹具
   (`tools/fixture-daemon.mjs` + `test/fixtures/scenes/`) 或临时目录中的合成数据。
5. 不把“个人更喜欢”的布局、配色、动效、文案写成缺陷。缺陷必须能引用：
   规格章节、设计令牌、可访问性规则、或可复现的交互/几何问题。
6. 若规格没有覆盖某个设计选择，记录为「规格空白」，不要判定为缺陷。

```cmd

```

另开一个终端：

```cmd

npm run test:ui
npm run test:electron:console
```

页面访问：`http://127.0.0.1:39490/ui/console.html#overview`（其它页替换 hash）。
截图矩阵：

```cmd
cd /d "<仓库根>\dock"
node tools\shots.mjs --page console --console-pages overview,context,usage,stats,quota,vendors,roles,settings,about --theme light,dark --viewport 960x680,760x560 --base http://127.0.0.1:39490
```

取证要求：

- 每个结论至少附一项：截图路径、选择器、`getBoundingClientRect()` 数值、
  `getComputedStyle()` 数值、axe 输出、或交互前后状态。
- 不凭缩略图或记忆判断；以实际渲染与测量为准。
- 对照规格时引用章节标题或令牌名，不引用实现者解释。

## 5. 检查清单

### A. 信息架构与导航

- 侧栏分组、顺序、图标、选中态是否与规格一致。
- 9 个入口是否都可到达；`Ctrl+1…7`、刷新后停留页、`Esc`、`Tab` 顺序是否符合规格。
- 视角切换（跟随吸附 / 四个 agent）是否改变数据口径，且不改变宠物吸附状态。
- 窄窗口（<860px）侧栏收窄后，导航是否仍可识别、可到达。

### B. 布局与视觉系统

- 设计令牌的使用：是否有硬编码颜色/字号/间距绕过 `tokens.css`。
- 字号：可见文本是否 ≥12px；字号是否落在允许的 8 档内。
- 对比度：正文 ≥4.5:1、大字 ≥3:1；浅/深两套都测；徽标文字在 12% 底色上是否达标。
- 间距/圆角/阴影：卡片内边距 16、卡片间距 16、页面左右 24 的偏差是否可复现。
- 溢出：无横向滚动；长标题/模型名/金额是否截断并可通过 tooltip 读取；数字不换行。
- 栅格：同一行卡片高度一致；两栏在 760/960/1280 下的折叠是否符合规格。
- DPI：DPR 1/1.5/2 下元素尺寸、命中区、截图是否一致。
- **窗口标题栏**：在最小宽度 760×560 与浅/深两套下，右上角原生最小化/最大化/关闭按钮不得裁切版本号、连接状态或标题栏底部分隔线；版本号必须完整可读。
- **图表悬停**：ColumnChart 悬停时虚线、明细气泡不得被裁切；气泡内容要含日期、合计与分项。

### C. 组件状态

逐项检查组件在 default / hover / focus / active / disabled / loading / error 下的表现：

- Button、IconButton、Toggle、Input、Select、Segmented、Card、Badge、ProgressBar、
  Gauge、StackedBar、AreaChart、ColumnChart、Table、EmptyState、Toast、Dialog、
  Skeleton。
- 所有交互元素是否有可访问名称、可见焦点环、≥32×32 点击区。
- Toggle 是否绑定 label 或 `aria-label`；Select/Input 是否有关联标签。
- Dialog/Drawer：`Esc` 关闭、焦点陷阱、关闭后焦点回到触发者、遮罩点击行为一致。
- Toast：出现/消失时间、`role="status"`、复制等反馈是否走 Toast。

### D. 数据呈现

- 一个数字是否只在一个地方当主角；同一金额是否在多个卡片重复且无层级差异。
- 金额/积分/百分比/Token 的单位是否紧贴数字；多币种是否有切换且不混算。
- 缺失数据是否显示「暂无/不可得」及原因，而不是 0 或空进度条。
- 置信度徽标（精确/推算/不可得）是否与数据来源一致。
- 图表：坐标轴、图例、阈值线、悬停提示、空态、`aria-label` 是否完整。
- 极端值：`¥12,345,678.90`、40 字中文标题、36 字符模型名是否溢出或遮挡。
- 过期/离线数据是否有明确标识；SSE 断线是否显示「连接中断，重试中…」。

### E. 交互与状态保持

- 总览在 SSE 更新后是否只改变化节点；滚动位置与展开状态是否保持。
- 上下文页切换会话/范围后，环、构成、趋势、会话表是否同步。
- 用量页三组筛选、搜索、排序、导出内容是否与当前筛选一致。
- 额度页校正对话框提交后数值是否变化；筛选/排序是否保持。
- 厂商页配置密钥后是否只显示掩码；测试连接结果是否可见。
- 角色页导入/删除/切换后，选中态与宠物层是否同步；队列/模板保存后可读回。
- 设置页每次改动是否立即生效并持久化；失败是否回滚并 Toast；搜索后分组是否完整。
- 弹层、对话框、Drawer 是否会被窗口边缘裁切（760×560、DPR 2）。
- 菜单/快览卡打开后，点屏幕其它位置是否在 0.5 秒内可靠关闭（含快速点击）。

### F. 可访问性

- 自动化：`@axe-core/playwright`，浅/深两套，`critical`/`serious` 必须为 0。
- 键盘：仅用键盘完成导航、切页、打开/关闭对话框、切换 Toggle/Segmented、
  提交表单；焦点顺序合理。
- 图表 SVG 是否有 `role="img"` 与可读 `aria-label`；装饰图标是否 `aria-hidden`。
- 页面标题层级、表格表头、`aria-live`（气泡/Toast）是否正确。
- 颜色之外是否有第二通道（图例文字、百分比、虚线）。

### G. 文案与反馈

- 中文标点、24 小时制、千分位、相对时间（「2 小时后重置」）是否一致。
- 错误文案是否说明原因与下一步动作（重试/去配置/重新登录），而非堆栈或错误码。
- 空态是否说明为什么空、如何出现数据。
- 是否存在开发者诊断文本出现在用户菜单/主界面（规格禁止）。

### H. 宠物层

- 角色透明边是否点击穿透；不透明区域是否可拖动/点击。
- 胶囊主数字、宿主图标、上下文迷你环、悬浮标记是否与规格一致。
- 气泡：不出屏、按象限翻转、点击关闭/推进队列、自动关闭时间可配。
- 快览卡/菜单：是否完整在屏内、可用键盘替代路径（托盘菜单）。
- 四个吸附象限的位置与镜像是否正确；高 DPI 下是否有偏移。
- 吸附模式下宿主不在前台时，浮层应被其它窗口盖住/隐身，而不是永远置顶。
- 桌宠模式浮在全屏窗口上时，点击角色位置必须穿透给全屏应用（不触发角色、不播音效）。
- 气泡与大快览卡同时打开时不得互相遮挡。
- 音效开关/音量是否生效；勿扰/隐藏金额是否只影响显示、不改数据。

## 7. 严重度定义（客观口径）

- **P1**：核心页面不可用、关键信息不可读/不可达、可访问性阻断（键盘无法完成主流程）、
  数据展示错误会误导决策、或违反文档硬约束。
- **P2**：与规格不符但有绕行方式；布局溢出/遮挡；对比度或点击区不达标；
  状态反馈缺失导致操作不确定。
- **P3**：文案、间距、边界状态、规格未覆盖的细节；不影响主流程完成。

评级只依据可复现的影响，不依据审美偏好。

## 8. 禁止事项

- 不写主观审美判断（“好看”“高级”“不够现代”“建议改成…”）。
- 不要求与 UI-SPEC 无关的重设计、换框架、换图标库、换配色。
- 不把截图缩略图上的观感当作证据；必须给出测量或可复现交互。
- 不修改 UI 代码、不提交、不推送、不打 tag、不发 release。
- 不在报告中粘贴真实密钥、token 或用户数据；截图需避开真实凭据。
